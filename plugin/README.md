# Reader（阅读）

一个 DeepSeek Harness 客户端插件：导入电子书，逐句精读——**听朗读**、**跟着语音打字**、**朗读后与原文比对**。

全部能力都在页面里跑：文件不出本机，语音用系统自带的 Web Speech API。**书库由宿主托管并落盘**（见「书库存在哪里」），所以桌面应用、浏览器、换个端口、重启之后，看到的都是同一批书。

---

## 功能

| 能力 | 说明 |
|---|---|
| 导入 | 拖拽或点选导入 **EPUB / TXT / Markdown / HTML / PDF**；PDF 走懒加载 chunk，不拖慢首屏；导入时底部浮着**进度卡片**（阶段 + 页/章计数 + 进度条） |
| 书库 | 书架式首页：顶部分段导航（书库 / 精读 / 生词本）、**READ / PLAYED / READING SPEED** 三张统计卡、**缩略图网格**（默认）/ 列表切换、搜索；EPUB 封面自动抽出缩成小图，没有就生成占位封面 |
| 每本书的操作 | 封面左下角 ▶ **直接朗读**、右下角 ⋯ 菜单（两个圆钮**常驻可见**，不必悬停）：**词频统计**（全书高频词条形图）、**查看详情**（作者/格式/章节/段落/词数/进度/已读词数/时长/加入时间/源文件）、**查看源文件**、**下载源文件**、**重命名**、**删除** |
| 源文件 | 每本书的**原始文件**（导入时那个 EPUB / PDF / TXT）由宿主**存下来**，跟着书库一起落盘：菜单里**查看源文件**能打开预览（PDF 逐页渲染、EPUB 按 spine 顺序显示原始章节、TXT/MD 显示原文、HTML 在禁脚本的 iframe 里显示），**下载源文件**能把原件带走，文件名就是导入时的那个名字 |
| 阅读情况 | 书库顶部汇总：本书数、在读、**已读词数**、**累计时长**；每本书显示进度百分比与已读词数 |
| 整段展示 | 精读页永远显示**整个自然段**，段内句子全部可见；当前练习句高亮，其余句子淡出 |
| 练习范围 | 「逐句 / 整段」一键切换：逐句＝只练当前句；整段＝整段一起练（打字、朗读、跟读都跟着变） |
| 听读 | 朗读当前练习单元，按 word 边界高亮当前词；可调语速（0.5x–2x）与语音（**音色按书的语种给**：英文书给英文音色，中文书给中文音色）；**播放范围可选段落 / 章节 / 全书**，可设循环次数、定时停止与**自动播放** |
| 打字 | **原位打字**（参考 Type to Learn）：段落本身是打字面，当前词高亮，打错的字符就地标红；底部的打字条装着准确率/速度、词进度、静音、等宽词输入框、重试 / 听一遍 / 语速；**语音逐词跟随打字** |
| 朗读 | 录音时有三点脉冲与 mm:ss 计时，**并且边说边标**：每 1.9 秒把已录到的音频再转写一次，和原文做词级比对，读对的词当场变绿、读错的词变红，状态行显示「录音中 · 已匹配 N%」，**读完一句自动停止**（音量回落 2 秒即判定读完，不必手点停止，随后立刻开始最终识别与分析），控制条上方常驻一条**精简点评**：语音 / 语调 / 音准三个维度 + 一条建议，点击才展开完整面板（实时版只显示匹配度，停止后才是完整的漏读/多读与三维评价）；**识别结果直接标在原文上**（读对=绿色、读错=红色波浪线、漏读=琥珀色点线，鼠标停在读错的词上能看到「你读成了什么」）；**语音、语调、音准（文本匹配）**三维评价与建议在段落右侧的**发音分析**面板里（识别出结果后出现），可一键听标准发音、回放自己的录音、看识别原文。语音/语调来自录音的音量、停顿与音高估算，不冒充音素级发音评分；不支持识别时降级为录音回放 |
| 点词查词 | 点段落里任意一个词，弹出**词卡**：音标、词性、中文释义、例句（带翻译）、这个词在当前句子里怎么理解——由宿主已配置的大模型实时生成 |
| 生词本 | 词卡里 ★ 收藏；左侧抽屉可查看全部生词、环形进度（Known / Learning / To learn）、今日新增、搜索与分类筛选 |
| 间隔复习 | 新收藏的词立刻进入「待复习」队列；复习按 1/2/4/7/15/30 天递增排期 |
| 符号替换 | 打字设置里可配置「原符号 => 你实际敲的字符」（如 `—` => `-`），判定按替换后的目标进行 |
| 段落工具 | **每一段文本的右侧有五个按钮**：✏️ 记笔记、🌐 只翻译这一段、▶ 听这一段、⌨️ **就地切到打字练习这一段**、🎙 **就地切到朗读打分这一段**（后两个直接把模式切过去并跳到这一段，不用先去顶栏切模式再回来找段落）；朗读模式出结果后多一个**波形按钮**打开发音分析。鼠标移到那段才出现，**并且固定在那一行**：按钮列比一行字高，鼠标往下够最后一两个按钮时会落到下一段的范围里，所以段落实际拥有哪个"当前段落"由指针事件跟踪，隐藏的按钮与容器都不接收指针（否则下一条看不见的按钮会抢走鼠标）；触屏上只在正在读的那一段下方常显 |
| 思维导图 | 阅读条上「生词本」右边一个图标：让模型把**当前这一章**整理成一张思维导图，三种布局可切，点节点能跳回书里对应的那一段 |
| 音频播客 | 阅读条上再往右一个耳机图标：让模型把**选定的章节或全书**改写成**双人英文对话播客**（主持人与嘉宾两个音色），逐句朗读，边听边看逐字稿，还能说话或打字插话 |

## 中文书也能读

切分层原本是按英文写的，于是中文书**打开是一片空白**：一整段被当成一句话（`Sentence 1/1`），
一个词都切不出来（`0 words`），练习区没有内容可练。现在中文是一等公民：

| 原来（英文假设） | 现在 |
|---|---|
| 句末只认 `.` `!` `?` | 也认 `。！？` 和 `……`；中文标点**后面不需要空格**就断句 |
| 词核心只有 `[A-Za-z0-9]` | 汉字**一字一词**（按码点切，生僻字不会被劈成两半），拉丁词照旧整词 |
| 标点必须紧挨着词才算词的尾部 | 落在两个词之间的**悬空标点**（`，」—（《` 等）会挂到词上，不再凭空消失 |
| 词与词之间插空格 | 中文**不加空格**（不然会显示成「你 好 。」） |
| 音色只列英文，识别固定 `en-US` | **音色与识别跟着书的语种走**：中文书配中文音色，识别用 `zh-CN` |

悬空标点这一条不是小事：修之前**2.37% 的字符在阅读区直接消失**（弯引号 1447 个、逗号 172 个、
破折号 152 个……），因为阅读区只渲染词，词之外的字符就没有地方去了。修之后是 **0.09%**。

中文书的词数口径也变了：以前一个字都切不出来（总词数 514），现在一字一词（2305），
所以**进度百分比会变小**（比如 35% 变成 8%）——这是更诚实的数字，不是数据丢了。

语音方面：宿主现在把**中英文音色一起给**（实测 MiniMax 有 80 个：英文 16、中文 64），
本机也有中文系统音色（婷婷 / 美佳 / 善怡）。

## 阅读条的样子

阅读条分成三段，用一根细线分开，眼睛读起来就是三件事：

```
←  书名（这一行的标题）  │  [章节 ▾]  18/874 · 1/4  │  笔记 思维导图 耳机 [生词本 3] │  20 words  0 to learn  est. 1 min  Known 100%
```

- **书名领读**：书名是这一行的标题（14px 半粗），后面才是位置和操作。
- **位置**：章节是一枚 chip（不是表单框），右边是紧凑的位置 `18/874 · 1/4`；完整写法
  「第 18/874 段 · 第 1/4 句」放在 tooltip 里。
- **操作**：笔记、思维导图、耳机三个图标按钮排在一起，生词本按钮收尾（带数量角标）。
- **数字**：这一段的统计最轻，排在最右。
- **窄面板不挤**：阅读条看的是**面板自己的宽度**（不是窗口宽度），面板一窄就先收统计，
  再收位置，最后收章节 chip —— 书名永远留在那里。

## 思维导图与音频播客

阅读条上，**动作区**里有两个图标按钮（生词本按钮的左边）：

| 按钮 | 作用 |
|---|---|
| 思维导图（中心节点带分支） | 打开当前章节的思维导图：中心是主题，一圈是一级分支，分支外面是要点 |
| 耳机 | 打开当前章节的音频播客：左边是节目列表，右边是逐字稿，底部是播放条 |

两者的范围都是**你正在读的那一章**（章节下拉里的当前章）。换章再打开，会按新的一章重新生成。

### 思维导图

- 模型返回的是一棵两层的树：中心主题 + 3–6 个一级分支，每个分支 2–4 个要点。
- **三种布局随时切**（弹窗头部，切换不重新请求模型、不丢数据）：

  | 布局 | 样子 |
  |---|---|
  | 思维导图 | 径向：主题在圆心，分支按扇区分到左右，要点在分支外面 |
  | 逻辑图 | 从左到右：根在左，分支一列，要点一列，每个分支站在自己那组要点的中间 |
  | 纵向树 | 从上到下：根在上、分支一行、要点一行，根水平居中 |

- 标签最多折成两行；要点下面那句补充说明不画出来，鼠标停在方框上有原生提示。
- 「重新画一张」可以再要一次；图太大时圆环会自动外扩，保证方框不重叠。

#### 点节点跳回书里

模型给每个分支和要点都附一句**从原文逐字抄下来的英文**（`quote`）。插件拿这句话在章节里定位：

- **点节点** → 节点被选中（蓝色描边），弹窗底部出现一条动作条：节点标题 + 那句原文 + 一个「跳到这一段」按钮。
- 点「跳到这一段」→ 导图关掉，阅读页跳到那句话所在的那一段（段落的第一句）。
- 原句在书里没定位到（比如模型改了措辞），就不给按钮，只说一句「这个节点在书里没有对应的段落」。
- 定位是**逐句全文匹配**（忽略大小写），所以模型只要抄对原句就能跳准。

### 音频播客

- 模型把选定的范围改写成**英文双人对话**（主持人提问、嘉宾讲解），存成一期节目。
- **音频不存**：只存台词，播放时逐句合成，所以本地库里只有几 KB 文字，不会越用越大。
- 播放条：上一句 / 播放停止 / 下一句 / 语速 / 第几句。点逐字稿里的任意一句可以从那里开始念。
- 节目按书存，可以随时翻出来重听，也可以删。

#### 主持人与嘉宾是两个音色

播客左侧「音色」区块里有两个下拉：**主持人音色**和**嘉宾音色**。

- 默认分配：主持人沿用**你正在用的朗读音色**（听着熟），嘉宾拿列表里第一个**不同于它**的英文音色——所以这档节目听起来是**两个人**，不是一个人念两段。
- 随时可以换；换完立即生效，下一句就用新音色。
- 节目结束或关掉面板时，**朗读音色会还回来**（播客不会把你的朗读声音换掉）。
- **你自己说的那一句不配音**：它在逐字稿里（琥珀色的「你」），但声音是你的，不需要再听一遍。

#### 一期节目讲什么范围

弹窗头部有一个**范围下拉**，可以选：

| 范围 | 说明 |
|---|---|
| 第 N 章 · 章节名 | 每一章都能单独出一期 |
| 全书 | 一期讲完整本书的脉络 |

- 选「全书」时，模型拿到的是**结构 + 每章开头**：书名、目录、每章的前若干字。整本书塞不进一次请求，也不该塞——一期节目讲的是**主线**，不是逐章复述。
- 范围换了，之前生成的节目还在（节目列表按书存，每一期都记着自己讲的范围）。

#### 播放时可以插话

播客放着的时候，你可以**说话**也可以**打字**：

1. 按**麦克风**（能录音时）→ 节目**停下来等你**，按钮变红（正在录音）。
2. 说完再按一下 → 你的话被**转写成文字**，作为「你」的一行台词进入逐字稿。
3. 模型拿到这句话和节目到目前为止的对话，**主持人接住它**（2–4 句），然后节目从那儿继续往下播。
4. 你说的话和主持人的回答都**存进这一期节目**，下次重听时这段对话还在逐字稿里。

**打字插话**走的是同一条路：逐字稿下面有一个输入框，打字回车就插话——**模型会解释，然后节目继续**，逐字稿随之更新。

> **为什么桌面应用里录音用不了**：浏览器只在**安全上下文**（https 或 localhost）下才暴露麦克风。桌面应用的窗口是从自定义协议加载的，不是安全上下文，所以 `navigator.mediaDevices` 根本不存在（报「当前环境不支持录音」）。
>
> 插件会**自己探测**这件事：不能录音时麦克风按钮消失，改成一句说明 + 打字输入框。想用真语音，就在**浏览器**里打开 `http://127.0.0.1:<端口>`（localhost 是安全上下文，麦克风可用）；用桌面应用就用打字插话，功能完全一样。

- 转写走的是宿主那条 MiniMax 通道（和「朗读」用的同一套语音服务），所以**英文识别最准**。
- 听不清或者通道不可用时，会明确告诉你「没听清，再说一次？」，不会静默失败。

> **这两个功能改的是宿主半边**（`index.js` 与 `src/host/ai.js` 多了 `mindmap`、`podcast`、`podcastReply` 三个 AI 方法），**需要重启一次 Harness 应用**才会生效；只刷新页面是不够的。

## 怎么看窗口是不是跑着旧 bundle

右上角**书架菜单（⋯）**最下面有一串**构建时间戳**（例如 `2026-10-25 16:59`）。桌面端不会自动重新加载插件的前端代码，所以改完代码后要 **⌘R 刷新**；时间戳对不上就说明窗口还是旧的。

> 早先这串时间戳是写在书库标题旁边的。标题和顶栏的页签重复，已经删掉；时间戳跟着挪进了书架菜单。

## 页面出错的兜底

**页签内容**外面包了一层**错误边界**：某个区块渲染出错时，不再是一片空白，而是显示「阅读器遇到问题，停止了。」+「你的书和笔记都还在，重新加载一般就能恢复。」+ 具体的错误信息 + 一个重新加载按钮。

边界在**页签内容**这一层，不在整页：

- 顶栏（书库 / 精读 / 生词本）**始终可用**，崩溃了还能切走
- 只有出问题的那个区块被替换
- 崩溃页会显示**错误原文和出错的文件位置**，桌面端不用开 devtools 也能把原因报给我

## 界面约定（对齐 TingYue）

- **填充按钮**（播放/朗读/复习）hover 时保持填充，只轻微变暗；描边按钮 hover 才填浅灰；禁用态是灰底灰字。
- **生词本抽屉**只占插件自己的区域，不遮挡宿主界面；抽屉和页面两种形态共用同一套排版（进度环 + 三项统计 + 筛选 + 搜索）。
- **阅读页**按句分组但不断行；生词按状态上色，模糊模式下模糊落在词上（filter 不能作用于行内元素）。
- **阅读页左上角有「退出当前书籍」**：一个返回箭头，点了就回到书库（阅读时长在退出时落盘，不会丢）。
- **听读模式可以用键盘翻页**：`←` 上一句 / `→` 下一句（练习范围是"整段"时就是上一段/下一段）。切到打字模式后方向键让给输入框，界面里的提示行也会写明这一点。
- **朗读模式有兜底**：桌面端通常没有可用的语音识别服务，识别一失败就自动切换成「录音回放自评」，而不是给一条死路。
- **云端朗读有两层保险**：点播放时先用一段静音音频解锁播放权限（否则浏览器会在网络往返之后拒绝播放）；云端音频放不出来时立刻回落到本机合成。
- **内容区域是固定的纸面**：纸面（暖纸底 + 左侧铜色进度条）撑满顶栏与底部控件条之间的整块区域，**上下滚动时移动的是框里的文字，不是整张纸**；页边、圆角、阴影和进度条都不跟着滚动。纸面不会被空出一大块空白，也不会被长文顶长。每页按框高自动拟合（装不下就少一段，最低 2 段，装得下就加一段）；窗口小到连 2 段都装不下时，底边那一行用渐变淡出而不是被硬切一半。判断「装不装得下」量的是**最后一段的底边**，不是滚动容器的高度——容器比内容高时 `scrollHeight` 恰好等于容器高度，会被误读成「刚好填满」，页面就会永远停在少一段的状态、在纸面底部留一大块空白。现在空档超过 3 行就再加一段；新加的那段即使溢出，只要还能露出 2.5 行以上就保留，底部渐隐提示还有下文；只有章节/全书读到头才允许留白。
- **底部永远只有一条控件条，并且跟着模式切换**：听读是播放条（浮在纸面下方），打字是打字条，朗读是朗读条。**每条都只有一行**（打字条约 61px、朗读条约 51px）；朗读条**左边是一个独立的主按钮**（铜色胶囊「Start reading aloud」，36px 高、点击即录），旁边是一枚 **ⓘ 信息图标**——「怎么用」的说明只在鼠标悬停时以 tooltip 出现，不再常驻一行被截断的提示语；中间只在真有状态时显示（录音中 / 已匹配 N% / 识别中 / 已识别·准确率 / 没有识别到内容）；ⓘ 旁边是 **Auto 胶囊**（自动下一句）：打开后这句读得够好（匹配度 ≥ 80%）就自动翻到下一句并**自己开始录音**，读不好则停在原句等你重读，实现「一直读下去」的连读练习，右边只有重试、发音分析与翻页。练习条不会浮在正在练的句子上，也不会在纸和条之间留出一大片空区。
- 工具栏用矢量图标，不用表情符号。

## 视觉系统：铜色与书页边缘

阅读器不再直接拿宿主的 `--dsw-alias-bg-layer-*` 画卡片：**浅色主题下宿主这四层全是 `#ffffff`**，卡片和画布一样白，只靠一道 4% 透明度的描边区分——整页看着就是"素"和"暗"。

所以插件自己声明了一组令牌，作用域是 `.er-page`（浮在面板外面的词卡、笔记浮层、模式浮层也带着同一组，因为它们被挂到了 `document.body` 上）：

- **四级表面** `--er-surface-0/1/2/3`：由宿主的 `bg-base` 和 `label-primary` 按 6% / 11% / 16% 混出来。浅色深色都分得开，宿主换主题也跟着变。
- **两道描边** `--er-line`（11%）和 `--er-line-strong`（18%）。**一条边只画一次**：两道半透明描边叠在一起会变成一条亮缝。
- **两层阴影** `--er-shadow-card`（卡片）和 `--er-shadow-float`（弹层），再加一道 `--er-edge`（顶部 1px 内高光）。近黑的表面上阴影看不见，**内高光才是"浮起来"的那个信号**，所以卡片两个都要有。
- **一个色相** `--er-accent`：**铜色**（浅色 `#9a6d1f`，深色 `#e0b558`）。纸是暖的，金子读起来像"书"而不像"工具"。

铜色只出现在三处：**主操作**（填充按钮）、**当前状态**（选中的模式、当前词、进度条）和**一个签名装置**——见下。

### 书页边缘（签名装置）

正文列是插件唯一自己拥有的表面：

- **暖纸** `--er-paper`（底色里掺一点铜色）和**赭墨** `--er-ink`（浅色 `#2a2620`，深色 `#e6dfd0`）；
- 正文列**左边钉一条 3px 的铜色进度条**，读到哪儿填到哪儿（`--er-progress`）；
- 顶部一道内高光，底部一层软阴影。

行长用 `ch` 约束：默认 **68ch**（窄 62ch / 宽 92ch / 铺满），落在 60–70ch 这个舒适区间里。

### 排版、圆角、动效

- **字号只有 12 / 13 / 14 / 16 / 18**，字重只有 400 / 500 / 600。层级靠颜色和字重，不靠字号。正文的大小是学习者自己调的，不算在这个台阶里。
- **圆角只用宿主的一档**：卡片 `--dsw-radius-md`（12），弹层 `--dsw-radius-lg`（16），小控件 `--dsw-radius-sm`（8），微控件 `--dsw-radius-xs`（4），药丸 `999px`，圆 `50%`。
- **动效**：hover 100ms、状态变化 200ms、弹层 240ms，一律 `cubic-bezier(.23,1,.32,1)`；按下有 `scale(.97)` 的反馈；`prefers-reduced-motion: reduce` 时时长归零。
- **图标用 `src/ui/icons.js` 里的 SVG**，不用表情和文字符号。

## 模式行是吸顶的

听读 / 打字 / 朗读、练习单位、填空、全文翻译这一行**固定在阅读区顶部**，正文滚动时它不动，控件永远够得着。

吸顶必须**自带不透明底色**（`var(--er-surface-0)`，和它所在的表面同一个值）：它下面就是正在滚动的正文，透明的话文字会从 chip 之间的缝里穿过去，读起来像两行字叠印在一起。手机档这一行改成**横向滚动的一条**，同样有底色（见下节）。

## 移动端与响应式

整套界面在**手机、平板、窄面板**里都要能读完一本书、能点得动；桌面端保持原来的铜色 / 石墨 / 纸的性格不变。

### 断点与判断方式

| 档位 | 宽度 | 判断方式 |
|---|---|---|
| 手机 | ≤ 600px | `@container erpage (max-width: 600px)`（面板宽度，不是窗口宽度） |
| 平板 | 601–900px | `@container erpage (max-width: 900px)` |
| 桌面 | ≥ 901px | 默认样式 |

- **面板宽度用容器查询，不用媒体查询**。桌面应用里侧栏一开，面板可能只剩几百像素而窗口还是 1440——按窗口判断会把"窄面板"当成桌面。`.er-page` 声明 `container-type: inline-size; container-name: erpage`，读条里原本就有的容器查询继续复用（`@container (max-width: 1040px)` 先收统计，再收位置，最后收章节）。
- **只有挂到 `document.body` 的浮层才看视口**（词卡、学习模式、笔记、播放设置，它们逃出了面板的滚动容器与层叠上下文）。这些用 `@media (max-width: 600px)` 切底部 sheet。
- **触屏尺寸用 `@media (pointer: coarse)`**：平板和触摸笔记本也算触屏。它负责把可点元素抬到 44×44；手机档再在这些基础上做布局。开关的轨道只有 26px 高，但按钮盒子是 48×44，轨道由 `::before` 画——看得见的是小轨道，点得到的是大盒子。

### 手机端各页面的形态

- **顶栏**：一行。两个 44×44 圆钮（导入 / 在线书库）+ 三段 tab + 书架菜单挤在同一行：tab 用 `flex:1 1 auto` 按标签宽度收缩，不再换行——390px 下三段都完整可见（原来 Vocabulary 会被切掉）。
- **书库**：统计压成一行三格（不是三张满宽卡），搜索与视图切换一行，书架 `minmax(132px, 1fr)` 两列；列表行的「朗读 / 开始阅读 / 删除」换成整行三个大按钮；导入进度卡贴底并让出安全区。
- **阅读条**：两行。第一行是返回 + 书名 + 笔记 / 生词本；第二行是章节下拉 + 位置 + 思维导图 / 播客。位置在手机上必须看得见，所以章节下拉用 `flex:1 1 0` 让出空间、位置不参与压缩（原来窄了会被藏掉或被章节下拉挤没）。书名优先于阅读统计：统计在 `inner < 1040px` 时先让位。
- **模式行**（手机）：两行，都不横滑。第一行是听读 / 打字 / 朗读（英文界面写作 Listen / Type / **Speak**），第二行是「逐句 / 整段 / 填空」+ 全文翻译图标。练习单位是仅次于模式的高频控制，钉在第二行常驻，不会藏在横向滚动的深处（手机档省掉了「Practice unit」这 80px 的文字标签，控件本身用 `aria-label` 保名）；全文翻译是阅读辅助，靠右对齐与练习单位分开，不混成第四个模式。
- **正文**：纸面全宽（左右 16px），默认字号封顶 18px、行高 ≥1.85（桌面上用户调过的大字号仍然在桌面生效）。
- **段落工具**：触屏没有 hover，三个按钮只在**正在读的那一段**下方常显（44×44），上下文段落保持纯文本——不给一屏铺满按钮。
- **底部工具条**：原来 78×286 的竖向工具轨改成横向一条（模式 / 填空 / 设置 / 目录），44 高、带图标和短标签（「学习模式」在手机档缩成「模式」，完整名称留在 `title` / `aria-label`）。
- **播放条**：贴底两行，`env(safe-area-inset-bottom)` 让出安全区。第一行 Play + 上一句 / 下一句 + 播放范围；第二行速度 + 音色 + 位置。整条**不横向滚动**（原来一行要横滑才够得着语速/音色），主播放键 44、次要键 44。
- **浮层**：词卡 / 学习模式 / 播放设置 / 笔记编辑器 = **底部 sheet**（最大 70–80dvh、圆角只在顶部、有 44px 关闭键；词卡另有一条可**向下拖动关闭**的把手，拖动超过 96px 即关闭）；弹窗（词频、详情、目录、笔记、思维导图、播客、源文件）在手机上**从底部升起、近全屏**；生词本抽屉变成**全屏层**。
- **键盘**：`responsive.js` 用 `visualViewport` 算出被键盘盖住的高度写进 `--er-keyboard-inset`，阅读区按这个值缩短，打字面板就不会压在键盘后面；输入框正文字号 ≥16px（iOS 不会因此缩放页面）。

### 沉浸式阅读（桌面 / 平板）

**练习面板（沉浸式）**用两条细线分成三个分区（选完任一项面板自动收起，焦点回到顶栏的模式按钮）：**模式**（听读 / 打字 / 朗读）、**练习单位**（逐句 / 整段 / 填空）、**阅读辅助**（全文翻译）。三区的选中态只有一种画法（同一档强调底色 + 强调色文字），高度统一 30px、字号 12.5px、组内间距 2px；禁用项（没有生词时的「填空」）压灰不可点。顶栏的「生词本」也收成图标 + 数量角标，不再是一块带文字的按钮。

桌面与平板的精读页以正文为主，不再让控件占据正文上方的连续几行：顶部只剩一条贴顶的圆角阅读栏，播放器收成贴底的小药丸。**右侧磁吸工具轨取消之后，模式改成零点击**：顶栏把 **Listen / Type / Speak 三段拼成一个分段控件**（当前模式铜色实心），点一下就切，不再「先开面板再选」。顶栏从此固定为一行、**不再折行**：分段控件 · 阅读辅助 · 目录 · **更多** · 生词本 · 设置；笔记 / 思维导图 / 播客这三件低频工具收进「更多」菜单（笔记有数量角标），菜单用同一套面板材质从按钮下方展开。剩下的设置放进 ✏ 按钮打开的面板，两组：**PRACTICE UNIT**（逐句 / 整段 / 填空）与 **READING AIDS**（六项辅助做成 2×3 小开关格：生词高亮 / 词义注释 / 全文翻译 / 模糊文字 / 双拼加粗 / 限制查词，每格一个状态点，说明收进 tooltip）。**面板里任何一次选择都不会把面板关掉**——设单位和开辅助通常是同一趟事，面板中途消失就成了二次劳动。桌面不再有第二条悬浮模式条，也没有第二个「阅读辅助」按钮——一个入口回答「我在做什么、做多大一块、开哪些辅助」。☰ 打开目录，⚙ 展开字号 / 字体 / 行距三个快捷调整项，弹层左下角新增**「恢复默认」**（一键回到默认字体 / 字号 / 行距），右下角「全部设置」进完整设置面板。阅读栏 8 个图标全部 icon-only，名称只留在 `title` / `aria-label` 里。正文宽度随面板伸缩，进度细轨保留，系统滚动条隐藏但滚动能力不变。手机端保留自己的底部工具条（模式 / 填空 / 设置 / 目录）与两行模式条，不切到这套悬浮面板。

### 阅读栅格：纸面列决定其余

桌面宽面板下阅读条、纸面、提示条曾经是三条互不相干左边线（304 / 364 / 409），看着像两张不同的栅格。现在：

- `.er-read-main` 与 `.er-read-bar-inner` 共用同一条**阅读框**：纸面列 + 内衬，整体居中；读条的 hairline 仍然横贯面板，内容收进阅读框里（工具栏全宽、内容有内衬）。工具轨撤掉后，阅读框的宽度就是纸面本身的宽度，不再额外加 78px（否则正文会整体偏左）。
- 纸面自己的盒模型改成 `border-box`，`max-width = 列宽 + 内衬`，窄面板下不会再被内衬顶出容器。
- 阅读框的宽度是**量出来的**（列宽是 `ch`，`ch` 只在正文自己的字体上才有意义）。量的必须是纸面**想要**的宽度：`--er-frame` 会把纸面约束住，直接量被约束的盒子会把自己的结果吃回去——窗口一旦变窄就再也不会长回来（实测 894 → 678 之后卡在 678）。所以量之前先把 `--er-frame` 设成 `none`，同一帧内量完再写回；同时监听 `window.resize` 和 `.er-page` 的尺寸变化，因为锁死时纸面本身不会有 resize 事件。

### 触控与键盘

- 触屏上可点元素 ≥ 44×44（`@media (pointer: coarse)`），桌面端保持原来的 28–32px 密度（鼠标的 WCAG 下限是 24）。
- 所有纯图标按钮都有 `aria-label`（手机上文字标签会被 CSS 隐藏，可访问名不能跟着消失）。
- `focus-visible` 保留；浮层里焦点不会跑出面板。
- `prefers-reduced-motion: reduce` 时动画时长归零，sheet 的进场动画也在内。

### 改完 UI 怎么看到

```bash
cd reader && node build.mjs   # 生成 client.js / client.pdf.js
```

然后刷新页面（客户端 bundle 不需要重启应用）。三档验收脚本在 `output/reader-qa/mobile/tools/`：`matrix.mjs`（三档 × 全部页面截图 + 量测）、`contrast-probe.mjs`（按计算色算对比度）、`frame-lock-probe.mjs`（1440→900→1440 的阅读框回归）、`desktop-check.mjs`（阅读栅格 / 吸顶底色 / 词卡避让）。

## 阅读页按窗口高度填充

阅读区不再是固定 6 段：它会**量一量窗口有多高，再决定放几段**（最多 40 段，最少 3 段）。窗口大就多放几段，小就少放，文字始终填满可视区，不留大片空白。

窗口尺寸变化时重新量一次——注意**不能**在尺寸变化时把页大小重置回去，那个更新会把"填满"的更新抵消掉（React 会把两次更新批成一次）。

页大小必须**收敛**：记住最后一个放得下的尺寸，一旦某个尺寸放不下就退回它并停止调整，否则文字会在读者眼前反复横跳。

## 组件里的 hook 必须在提前 return 之前

阅读器组件在没有书的时候会提前 return 空状态。**所有 hook 必须写在它前面**，否则两次渲染的 hook 顺序不同，React 的状态槽位会串位——表现是"状态明明改了，界面不动"。

同理，**提前 return 之前的 hook 不能直接取 `unit.` 的属性**。没有书时 `units` 是空的，`unit` 就是 `undefined`，`unit.text` 会在渲染期抛 `Cannot read properties of undefined`，比空状态早一步把整个页签打挂。依赖数组里要写 `unit?.text`。

## 书架上的按钮都要有反应

- 封面上的 **🎧** 是「朗读这一本」：打开书并**立刻开始朗读**（网格视图和列表视图都有效）
- 封面上的 **⋯** 打开菜单：词频统计 / 查看详情 / 生成封面 / 重命名 / 删除（**列表视图也渲染菜单**）
- 列表视图那一行另有「朗读 / 继续阅读 / 删除」三个按钮

## 书库存在哪里

**书库由宿主托管，落在磁盘上。**目录在当前 profile 里：

```
<profileDir>/reader/
├── books/
│   └── <bookId>.json      一本书一个文件（整条记录，含正文）
├── sources/
│   └── <bookId>.<format>  一本书的原始文件（导入时那个 EPUB/PDF）
├── vocabulary.json        生词本
├── notes.json             笔记
└── podcasts.json          播客逐字稿
```

### 书架不搬整本书

书库在磁盘上还是整本（学习者的数据原样保存），但**读出来**的时候不是整本。

| | 以前 | 现在 |
|---|---|---|
| 打开书架 | `books.list` 3.37 MB（六本书） | `books.summaries` **2.9 KB** |
| 翻三句话 | 6 × `books.list` = **19.27 MB** | 6 × `books.progress` = **288 B** |

- **书架用摘要**：`books.summaries` 只带元数据（书名、作者、进度、词数、封面地址），
  **不带正文**。词数由宿主算，用的是 `src/shared/**` 里的同一个切词器，两边永远对得上。
- **正文要时才取**：打开一本书、算一本书的词频，用 `books.get` 取**那一本**。
- **封面走自己的请求**：`/api/reader/cover?id=…&v=…&s=…` 直接给图片字节
  （没有 JSON 外壳），所以地址能直接放进 `<img src>`。`v` 是封面的哈希（换封面换地址，
  写进度不变地址），`s` 是封面字节数 —— 客户端**不下载就知道封面该不该缩小**。
- **翻句子不再重拉书架**：阅读进度是**就地改**本地那一条，不是重拉整个书架。
- **封面只存小的**：导入与 AI 生成的封面都缩到 320px 宽再存。书架画的是 168px，
  832×1248 的原图是浪费。旧书里还留着大封面的，**打开书架时后台缩一次**（一次性的）。

写回也走专用动作，跟 `books.progress` 同一个道理：**只传要改的那部分**，
宿主读出来、合并、写回 —— `books.cover`（换封面）只传那几十 KB 的封面，
不用把整本书在网络上搬两个来回。

`<profileDir>` 就是 `~/.dsh/profiles/<profile>`（拿不到时退回 `~/.dsh/reader`）。

### 为什么不是浏览器 IndexedDB

原来书存在**浏览器的 IndexedDB** 里。IndexedDB 按「源（origin）」隔离，于是同一个电脑上有好几份互不相通的书库：

| 在哪里打开 | 源 | 书库 |
|---|---|---|
| 桌面应用内嵌窗口 | `dsh-app://app` | 有书 |
| 浏览器打开 `http://127.0.0.1:63290` | `http://127.0.0.1:63290` | 空 |
| 下次重启，端口变成 63291 | `http://127.0.0.1:63291` | 又空 |

所以「在电脑上导入了书，刷新一下却看不见了」——书没丢，是**存在另一个源的 IndexedDB 里**。
宿主托管之后，桌面应用、浏览器、任何端口、任何时刻，看到的都是同一批书。

### 几条规矩

- **写入是原子的**：先写 `<file>.tmp`，再 `rename` 覆盖。断电或崩溃不会留下半个 JSON。
- **坏文件被跳过**：一块坏 JSON 不会让整个书库打不开，其余书照常列出。
- **记录原样保存**：不裁字段、不校验 schema，学习者的数据不会被宿主弄丢。
- **写进度只传进度**：阅读时每翻一句都会写一次进度，宿主在磁盘上读改写，**整本书不会在网络上搬两个来回**。

### 迁移：把已经在浏览器里的书搬上宿主

第一次打开新版时，插件会把**当前这个源**里已有的书（以及生词、笔记、播客）搬上宿主：

- 宿主该集合**是空的**且本地有 → 搬上去，全部成功后再清空本地副本。
- 宿主该集合**已经有东西** → 本地那份视为过期副本，不再搬（否则你删掉的书会复活）。
- 每个源只迁一次，标记写在 `localStorage` 的 `english-reader:shelf-migrated`。

迁移是幂等的：中途断了，下次重跑不会产生重复。

### 宿主不可用时怎么办

宿主半边要**重启 Harness 应用**才生效。在「已重启」和「还没重启」之间，客户端会一直用旧的
IndexedDB（读写都落在本地），并在宿主答复 `reader/unknown-method` 时自动切回来。
所以**先刷新页面、后重启应用**这个顺序不会把功能弄坏。

## 源文件：能看，也能带走

书库里存的是**解析后的正文**。但学习者导入的那本电子书本身也是他的东西，所以宿主把
**原始字节**也存下来（`sources/<bookId>.<format>`），和书库放在一起。

| 动作 | 在哪里 | 做什么 |
|---|---|---|
| 查看源文件 | 书库每本书的 ⋯ 菜单 | 打开预览：PDF 用 pdf.js 逐页渲染；EPUB 解开 ZIP，按 `container.xml → OPF → spine` 取出内容文档，在禁了脚本的 iframe 里显示；TXT/MD 显示原文；HTML 原样显示 |
| 下载源文件 | 同一个菜单 | 把原始字节下载下来，**文件名就是导入时的那个名字** |

几条规矩：

- **源文件存不住不影响导入**：书照样入库，只是这本书没有源文件，菜单里那两项是灰的。
- **元数据跟着书记录走**：宿主把 `source: { fileName, format, contentType, size, storedAt }`
  合并进书记录，于是书库一眼就知道这本书还能不能带走。
- **宿主不丢 `source`**：客户端把整条记录写回来时（改名、换封面）那条记录里往往没有
  `source` 字段，宿主持有磁盘上已有的那份。
- **删书会连源文件一起删**：书没了，文件也不留在磁盘上。
- 传输走独立路由 `GET/POST /api/reader/source`，**请求体和响应体都是文件本身**
  （base64 进 JSON 会白白胀大三分之一）。详见 `docs/CONTRACT-SOURCE.md`。

### 浏览器本地库升级不会卡死

兜底用的 IndexedDB 升级版本时，**还开着的旧窗口会挡住升级**（浏览器的规则）。所以：

- 连接上挂了 `onversionchange`：别的窗口要升级时，这个连接主动让路 ✓
- 升级被挡住时**先重试一次**（旧窗口通常一秒内就关），还不行就报错「本地书库正被另一个窗口占用，请刷新页面」，**绝不无限等待**

## 阅读笔记

阅读页顶栏有一个**笔记按钮**（带条数角标），点开是一个对话框：

- 上面是**当前那句话**（斜体引文），下面是一个输入框，写完点「保存笔记」
- 下面是这本书已有的笔记：每条带原文引文、你的文字、时间
- 每条笔记有「跳到这句话」（回到原文的位置）和一个删除按钮

笔记存在**宿主的书库里**（`<profileDir>/reader/notes.json`，按书分组），刷新、重启、换浏览器都在，不出本机。

## 每一段右侧的三个按钮（朗读模式多一个）

顶栏的笔记按钮管的是「当前这一句」；**每一段文本的右侧还有三个按钮**，管的是「这一整段」：

| 按钮 | 作用 |
|---|---|
| ✏️ 笔记 | 给这一段写笔记 |
| 🌐 地球 | 只翻译这一段，译文出现在这一段下面 |
| ▶ 播放 | 只朗读这一段（再按一次停止） |
| 〰 波形（仅朗读模式、出结果后） | 打开发音分析：语音 / 语调 / 音准三项评价、针对性建议、逐词结果、识别原文、录音回放与标准发音 |

朗读模式下的比对直接画在原文上，不再单开一张结果卡：读对的词是正文色 + 一条淡绿下划线，读错的词是红色波浪线（鼠标停上去显示「你读成了 X」），漏读是琥珀色点线；多读的词列在发音分析面板里。

- 三个按钮在段落右边的小沟里**横着排**（一行三个），**默认是隐藏的**，鼠标移到那一段才出现（键盘 Tab 过去也会出现）；触屏没有悬停，就一直显示。
- 横排而不是竖排是有原因的：一列三个有 82px 高，**比一行文字还高**，会把每个短段落都撑高，短段落下面就空出一大块地方。横排只有 26px 高，段落高度就只由文字决定，**段间距因此是均匀的**（10px）。
- 做过的按钮会**留下记号**：写过笔记是琥珀色（还带条数角标），翻过译是绿色，正在朗读是蓝色。

### 笔记

- 点开是一个贴着这一段的小编辑器：上面是这一段的原文（斜体，最多三行），下面是输入框和「保存笔记」。
- 存好的笔记列在编辑器下方，可以就地删除。
- 笔记挂在这一段的**第一句**上，所以顶栏的笔记列表里也能看到它，点「跳到这句话」会跳回这一段。
- 按 Esc 或点编辑器外面都会关掉。

编辑器是浮层：优先往正文右边（正文与面板边缘之间的空隙）开，空隙不够就贴着按钮往左开，不会被正文盖住。

### 翻译

- 点一下，这一段**单独**送去翻译，译文出现在这一段下面——和「全文翻译」开关放在同一个位置。
- 只请求这一段，不翻整页；顶栏那个「全文翻译」开关照旧是整页一起翻。
- 翻译失败（模型不通）时这一段**保持原样**，不塞一行空文本进去。

### 本机语音优先（Kokoro）

朗读默认走**本机模型**，本机没有才走云端。本机模型是 [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)（82M 参数，Apache-2.0），美式 / 英式各有一组音色，听起来是播音员，不是系统 TTS 的那种机械音。

安装（只做一次，不进入插件包）：

```bash
# 1. 一个只装语音依赖的 venv（复用系统里已有的 torch，不重复下载）
python3 -m venv --system-site-packages ~/.dsh/reader/tts-venv
~/.dsh/reader/tts-venv/bin/pip install kokoro soundfile

# 2. 模型权重（首次合成时自动下载到 HuggingFace 缓存，约 330MB）
```

首选音色：美式 `af_heart`（女声，最自然）、`am_michael`；英式 `bf_emma`、`bm_george`。都可在 `~/.dsh/reader/tts.json` 里换：

```json
{
  "local": {
    "enabled": true,
    "voices": { "en-US": "af_heart", "en-GB": "bf_emma" },
    "idleSeconds": 600
  }
}
```

工作方式：宿主第一次要朗读时启动一个本机语音进程（`src/host/kokoro-server.py`），模型只加载一次，空闲 10 分钟自己退出；它挂了或没装，就自动回到云端 MiniMax（`speech-2.8-hd`），并在播放面板里写明现在用的是哪一个。

实测（M1/M2 级别机器，同一段 5 秒文字）：本机首句约 2–6 秒（含模型加载），热机约 2 秒；云端 MiniMax 约 1.5–2 秒。音频按句缓存，重读同一句是 0 秒。
### 朗读与口音

**口音是先选好再读的，不是碰巧读成什么样。** 播放条上有一个 US / UK 开关（美式 / 英式英语），选择会被记住；句子朗读、点词发音、播客、发音分析里的「标准发音」全部用这个口音。

音色的挑选规则（`src/lib/voices.js`）：

- **只用这本书的语种、并且是所选口音的音色**：英文书只在 en-US / en-GB 的音色里挑，`en-IN`、`en-AU`、日语等音色一律不当候选人——之前「日本/印度口音的英语」就是这里漏了。
- **绝不用系统默认音色**：以前没选音色时不设 `lang`、也不指定音色，浏览器就用机器默认的那个（可能是日语），现在每次合成都会显式指定 `lang` 和音色。
- **玩具音色黑名单**：Albert / Bubbles / Zarvox / Grandma 这类 macOS 特效音色不参与挑选。
- **优先下载版音色**：装了 Samantha (Enhanced/Premium)、Daniel (Premium) 这类高质量音色时优先用它，其次是 Samantha / Daniel / Ava / Google US English / Microsoft Aria 这类旁白音色。
- **云端只留旁白**：MiniMax 的英文音色表里混着角色音色（UpsetGirl、SadTeen、Comedian）和外口音音色（Aussie Bloke），插件只取 8 个旁白级音色（Expressive Narrator、Trustworthy Man、Calm Woman…），语言不明的音色不再被当成英文；英式英语没有对应的云端音色时用本机的英式音色，而不是拿美音冒充。
- 云端语音模型从 `speech-02-hd` 升到 **`speech-2.8-hd`**（不支持时自动回退到 `speech-02-hd`）。
- 云端不可用时**不再静默降级**：播放面板里会写明原因（例如 Key 失效），并说明当前用本机哪个口音的音色。

- 点一下，这一段用**当前音色**从头念一遍；再按一次停止。
- 朗读这一段会**打断**正在进行的跟读（同一个语音引擎），翻页时也会停。
- 只念这一段，不动练习单元：你读到哪一句不受影响。

## 浮层都要躲开正文

「学习模式」面板和笔记编辑器都是**挂在 document.body 上的浮层**，用视口坐标定位：

- 「阅读辅助」面板开在阅读栏那枚铅笔按钮下方、正文右侧留白处，六行开关一行不少（工具轨撤掉后锚点改成顶栏按钮）。
- 早前它挂在工具条里、用 `position:absolute` 定位，结果被**吸顶的模式行**盖掉了第一行（模式行 `z-index:6`，工具条是 `z-index:auto`），看上去就像面板被切掉一块。改成浮层 + 视口坐标之后，谁也盖不住它了。

## 在线书库（Project Gutenberg）

书库页顶栏的 🌐 按钮打开在线书库：按书名或作者搜索，点「获取」直接下载、解析并入库。

- **书源**：Project Gutenberg（公版书），用的是官方机器可读目录 `pg_catalog.csv`（约 21 MB）和官方下载直链
- **目录放在宿主**：目录太大，不进 bundle；宿主第一次用到时下载一次，缓存在 `~/.dsh/reader/gutenberg-catalog.csv`（七天过期），之后在内存里搜索
- **下载很稳**：连接经常被切断，所以每个文件都按 Range 分块下载并重试，失败时回退到分块路径
- **导入即干净**：公版书自带授权声明与扉页，导入时自动去掉（`stripBoilerplate`）

## AI 封面

书里没有自带封面的，让 MiniMax 画一张：

- 接口：`POST /v1/image_generation`，模型 `image-01`，比例 `2:3`（书的标准开本）
- 提示词只给**书名**（图像模型把长标题和作者名都会写错），并明确要求「只出现书名，不要作者名、不要出版社」
- 图片在宿主侧下载成 data URL 存进书库（`<profileDir>/reader/books/<id>.json`），书架不依赖网络
- **书先入库、封面随后补上**：导入后立刻能看到书，封面几秒后自己换上；也可以在书的 ⋯ 菜单里点「生成封面」重画
- **画封面有反馈**：画的过程中书库里有一条「正在生成封面…」的提示，封面卡片上盖着一层转圈的遮罩；画完提示变成「封面已生成」，失败则说明失败原因（画一张要十几秒，不能让人干等）

## MiniMax 通道（语音 + 模型）

宿主半边持有 MiniMax 的 API Key，客户端通过 `/api/reader` 请求：

| 方法 | 作用 | 实现 |
|---|---|---|
| `status` | 通道是否可用 | `src/host/minimax.js` |
| `voices` | 英文系统音色列表 | `get_voice` 接口 |
| `tts` | 朗读一段文本 | `t2a_v2` 接口，返回 `data:audio/mp3;base64,…` 与时长 |
| `word` / `translate` / `breakdown` | 查词、翻译、拆句 | `chat/completions` 接口，模型 `MiniMax-Text-01` |

**Key 不进代码、不进 bundle**。读取顺序：

1. 环境变量 `MINIMAX_API_KEY`
2. 私有文件 `~/.dsh/reader/minimax.key`（权限 600）
3. 环境变量 `ENGLISH_READER_MINIMAX_KEY_FILE` 可改这个文件的位置（测试用它来关掉通道）

没有 Key 时：查词/翻译回落到宿主自己的模型，朗读回落到浏览器的 Web Speech API，学习者不会听到任何变化。

**引擎只报码，页面负责翻译**：识别/录音的失败在引擎里是机器码（`NO_RECOGNITION` / `RECORD_FAILED`），界面按语言给出人话，不再出现引擎里写死的中文串。

**朗读（Read aloud）也走 MiniMax**：桌面端拿不到浏览器的语音识别服务，所以朗读时**用麦克风录音 → 宿主把 WebM 统一转成 16kHz 单声道 WAV → 宿主转写 → 与原文逐词比对**，准确率、漏词、多词全部照常给。转写接口是 `POST /v1/speech_to_text`，模型 `asr-1.0`；WAV 转换由 `src/host/audio.js` 用 ffmpeg 完成（RIFF/WAV 输入直接透传）。宿主没配 key 时才回落到浏览器的 `SpeechRecognition`（多数桌面环境不可用），再不行就是纯录音回放自评。

**单词发音也走 MiniMax**（`src/lib/speech.js`）：点词、词卡上的喇叭、生词本里的喇叭，都先用云端音色念，失败才回落到浏览器自带语音。朗读整段用的是底部播放条上选中的音色；念单词时默认用选中的云端音色，没有就用第一个 MiniMax 音色。

**行为细节**

- 选中的音色带 `mm:` 前缀即为 MiniMax 音色；音色下拉里标着 `· MiniMax`
- 云端音频没有 boundary 事件，词的跟随高亮按**音频总时长平均分配**，比本机合成的固定节奏更准
- 云端合成失败（网络、额度、鉴权）自动回落到本机合成
- 这个 Key 对应的 API 根是 `https://api.minimaxi.com`，`api.minimax.io` 会拒绝它

## 封面与阅读速度的两个坑

- **列表视图的小封面**：两个圆形按钮（🎧 / ⋯）缩到 17px 并贴住下角，不会互相压住。
- **没有封面的书**：占位封面不是白板，而是一张渐变封面（首字母 + 一道细线），和真实封面放在一起不违和。
- **阅读速度的基线**：打开一本书时，**当前位置之前**的词不算你读过。少了这条基线，从中间打开的书会把前面几万词一次性算进阅读速度（出现过 10252 WPM 这种数）。另外速度超过 600 WPM 一律按"无数据"处理，不显示离谱的数字。

```
│                                                                            │   释义   │
│  衬线正文的整个段落（生词铜色高亮，可开启词义注释）                          │   填空   │

├ 播放 ◀ ▶ 循环 ───────────── 语速 1x · 语音 Albert(en-US) · 1/2 ─────────────┤
```

- **全文翻译**：模式行上有独立开关「Full text translation」，打开后每段下方实时生成翻译（按页并行，一次模型延迟）。**翻译成哪种语言在设置里选**：中文、English、日本語、한국어、Français、Deutsch、Español、Português、Italiano、Русский。语言用它自己的名字写着，模型收到的也是这个名字；宿主只认这张表里的语言，页面传什么别的都不会进提示词。换了语言，旧的译文立刻作废重翻。
- **顶栏的主次**：书名是标题（14px / 半粗 / 主色），段句位置是安静的说明文字（12px / 三级灰）；章节下拉有自绘的箭头，宽度封顶 200px。
- **提示语的位置**：阅读提示在正文卡片**内部的最上方**，不是浮在卡片外面；切到打字/朗读模式时它自动消失。
- **正文用衬线体**（书的样子），一屏显示**一整页（约 6 段）**：当前段是正文色，前后段落是上下文灰；翻句时当前段自动滚到视野内。
- **正文列是"一页纸"**：暖纸底、赭墨字，左边钉一条铜色进度条，顶部一道内高光——见「视觉系统」。
- **生词高亮**：收藏过的词在正文里是一层淡铜色（不再是黄底）；开「词义注释」后，释义以小字显示在词下方。
- **顶部进度条**：当前词数、待学词数、预计用时、已掌握比例。
- **目录**：书有多个章节时列章节；只有一章的书（长文）改为按段落列，每条带段落首句预览。
- **阅读栏右侧的图标**：练习模式分段控件、阅读辅助、目录、更多（笔记 / 思维导图 / 播客）、生词本、设置（详细的「全部设置」收在字号弹层里）。一行放不下时优先收进「更多」，不允许顶栏折成两行。
- **填空模式**：把这一段里你收藏过的词挖空，只练这些词。
- **底部播放条（听读模式）**：播放、上一句、下一句、播放设置、语速、语音、位置。切到打字 / 朗读模式时它整条让位给该模式自己的控件条，不会两条同时出现；打字条的语速是同一个设置，改哪边都生效。
- **朗读状态跟着当前那条 bar 走**：听读时是浮在播放条上方的胶囊（正在朗读 · 段号 · 暂停/继续）；打字和朗读时它是那条 bar 里的一行（同样有暂停/继续），所以不会压住词输入框，手机上也能暂停——手机没有播放条可退回。
- **播放设置（循环按钮）**：点底部的循环按钮弹出播放设置——**播放范围**（段落 / 章节 / 全书）、**循环播放**开关、**循环次数**（2 / 3 / 5 / 10 / 一直）、**定时停止**（关闭 / 10 / 30 / 60 / 120 分钟）、**自动播放**。按钮上带一枚角标，写着当前范围与遍数。播放时页面跟着朗读的段落走，词高亮不中断；学习者自己翻句仍然会停下朗读。这套设置存在本地，第二天回来还在。
- **自动播放**：打开后，翻到下一句/下一段就会自动朗读，不用再点播放；只在**听读**模式下生效（打字时语音跟着打字，朗读时机器不能抢话）。

## 阅读页的结构

```
┌ 章节选择器 ── 第 3/12 段 · 第 2/4 句 ── 书名 ┐
│ 固定的纸面（文字在框内滚动，纸边不移动）          │
│ 整个自然段（所有句子都在，练习句高亮、其余淡出）  │
│ [听读] [打字] [朗读]   练习范围： [逐句] [整段]   │
└ 底部控件条：听读=播放条 / 打字=打字条 / 朗读=朗读条     ┘
```

- **逐句**：当前句是练习目标，段内其它句子淡出作为上下文；「下一句」在段内推进，走完本段进入下一段。
- **整段**：整段都是练习目标；朗读一次读完整段，「下一段」跳到下一段。
- 顶部计数器始终同时给出「第几段 / 第几句」，不会丢失位置感。

## 打字模式（Type to Learn 模型）

段落本身就是打字面，不再另开一个大文本框：

```
┌────────────────────────────────────────┐
│ The first fristraph opens the chapter.  │ ← 打错的字符就地标红
│ It carries three sentences so the       │ ← 段内其它句子淡出作上下文
│ reader can check the whole block at once.│
└────────────────────────────────────────┘
┌ 62%  0 wpm ──── [ frist ] ──── 3/17 🔊 重试 听一遍 1x ┐
└ 打字条：准确率 / 速度 · 等宽词输入框 · 词进度 · 静音 · 动作 · 语速 ┘
```

- **逐词推进**：打一个词按空格提交并跳到下一个词；退格可以退回上一个词继续改。
- **打错就停在原地**：默认必须打对才能往下走（Type to Learn 的 "Forgive mistakes" 默认关闭）。
- **打字条**（贴底那一条，打字模式下它就是唯一的底部控件条）：准确率（打对的字符 / 已打字符）、速度（词/分或字符/分，可切换）、词进度、上一句 / 下一句、静音、等宽词输入框、重试 / 听一遍、语速；正在朗读时条顶还会多一行「正在朗读 · 第几段 · 暂停」。
- **设置面板**（齿轮图标）：字体（无衬线 / 衬线 / 等宽）、字号、行高、速度单位、宽容错误、隐藏输入框。
  设置存在本机 localStorage，跟随浏览器。

## 书库与个人阅读情况

- **封面**：EPUB 的封面按「`meta[name=cover]` → manifest 的 `cover-image` 属性 → 阅读顺序里第一张图」的优先级取出，
  客户端缩到 320px 宽导出 JPEG（SVG 原样透传）；没有封面时按标题生成渐变 + 首字母的占位封面。
- **展示方式**：默认缩略图网格，右上角可切列表；选择存在 localStorage。
- **每本书的菜单**：词频统计、查看详情、重命名、删除；封面左下角的 🎧 直接朗读这本书。
- **朗读时长**（PLAYED）：播放语音期间单独计时，与阅读时长分开统计。
- **搜索**：书名、作者、格式，按书名或作者过滤。
- **阅读情况**：阅读时累计时长与已读词数（每 15 秒与每次翻句写回），按本地自然日分桶，
  书库顶部汇总本书数 / 在读 / 已读词数 / 累计时长，单书显示进度与已读词数。

## 导入有过程反馈

导入一本书要几十秒（EPUB 解压 + 逐章解析，PDF 逐页抽字），**没有反馈就等于按钮坏了**。
所以面板底部浮着一张**导入卡片**：

- **四个阶段**：读取文件 → 解析正文 → 准备封面 → 写入书库；每一段占进度条的一部分
  （解析占大头，因为时间都在那里）。
- **能数出来就报数**：PDF 报「第 30/400 页」，EPUB 报「第 30/400 章」；数不出来的格式（TXT/MD/HTML）
  只报阶段名。
- **多本书一起导**：右上角是「第几本 / 共几本」，每本书在总进度里占同样一份。
- **不挡书架**：卡片浮在底部、内容区留出下边距；`pointer-events:none`，点不到也挡不住操作。
- **至少亮 0.7 秒**：小 TXT 几十毫秒就导完了，闪一下等于没看见，所以卡片有最短显示时长。
- **EPUB 解析每 8 章让出一次主线程**：否则章节循环是同步的，进度只会在最后一刻一次性跳完，
  中间的动画根本画不出来（`MessageChannel` 让出，比 `setTimeout` 便宜得多）。

进度模型在 `src/lib/import-progress.js`（纯函数，页面和卡片共用一份口径），
卡片在 `src/ui/import-card.js`，解析器通过 `parseBook(file, onProgress)` 汇报自己的进度。

## 点词查词怎么工作

1. 页面点词 → 客户端 `askAi('word', { word, sentence })`；
2. 客户端 POST 到宿主路由 `/api/reader`；
3. 宿主用 `ctx.agentDefaultModel.currentSelection()` 选模型、`ctx.llm.prepareCall()` + `prepared.stream()` 跑一次流式调用，要求模型**只输出 JSON**（解析失败自动重试一次）；
4. 词卡拿到 `{ word, phonetic, partOfSpeech, definition, examples[], contextNote }`。

宿主没配置模型、或调用失败时，词卡会显示中文错误，其它功能不受影响。
宿主路由在 `index.js`（插件的 Host 半边）。**改 Host 半边**后，在插件管理里把 Reader 关掉再打开即可热重载路由（宿主 HMR 通常也会自动重载；改到无法挂载时再重启应用）。客户端半边改完 `node build.mjs` 后刷新页面即可。

路由上的方法分两族：

| 方法 | 谁用 | 说明 |
|---|---|---|
| `word` / `translate` / `breakdown` / `mindmap` / `podcast` / `podcastReply` / `tts` / `asr` / `cover` / `voices` / `status` / `source` | AI 通道 | 见上面各节 |
| `shelf` | 书库 | `payload.action` 取 `books.list` / `books.get` / `books.put` / `books.progress` / `books.delete` / `vocab.*` / `notes.*` / `podcasts.*` |

`shelf` 的完整协议在 [`docs/CONTRACT-SHELF.md`](docs/CONTRACT-SHELF.md)。

## 「语音跟随打字」的具体规则

打字模式默认开启「语音跟随打字」，同步逻辑在 `src/lib/engine/sync.js`。
**一次只读一个词**：你正在打的是哪个词，机器就只读哪个词。整句一起读的话，
声音会跑在手前面，听到的已经不是自己正在写的那一句；逐词读才是「听到 → 跟着写」
那个节奏。

| 你的打字进度 | 朗读的行为 |
|---|---|
| 换到一个新词 | 取消当前这个词的朗读，**读新词** |
| 还停在同一个词 | 不打断它 |
| 这个词写错了 | **再说一遍**这个词 |
| 换练习单元 | 停止并复位，旧朗读的回调不会污染新单元 |

**标点怎么算**：书上把标点粘在词后面（"better,"），你要打的是词本身。
所以输入框里给的是 `better` 而不是 `better,`；而你照着书上打成 `better,`
（或把 "don't" 打成 "dont"）**也算对** —— 判定时会跳过标点，跟朗读那条路
（词级对齐）用的是同一套规则。词里的撇号和连字符是词的一部分，会留在输入框里。

## 已知边界

- **扫描版 PDF** 抽不出文字，会明确报错，请改用 EPUB / TXT。
- **语音识别**依赖浏览器的 Web Speech API：在 Chrome / Safari 可用；部分 Electron 运行时没有可用识别服务，此时朗读模式会提示并降级为「录音回放」自评。
- **不派发 boundary 事件的浏览器**（Safari / Firefox）朗读高亮会退化为按词估算，精度略低但不影响使用。
- **MOBI / AZW3 / FB2** 等格式未支持（缺少可靠的纯前端解析器），导入时会给出明确提示。
- **源文件预览只对导入之后的新书有**：早于这个功能的书，导入时原件没被留下，菜单里「查看/下载源文件」是灰的。
- **源文件预览的边界**：EPUB 只内联**当前那一章**的插图与样式（换章就重新内联），书里自带的脚本不会运行；PDF 按页渲染，扫描件在预览里看到的是原样图像。**下载下来的原件永远是完好的**。
- EPUB 章标题取正文首个 heading，其次取目录（TOC/NCX），最后退化为「第 N 章」。
- **宿主半边与客户端半边的生效方式不同**：`index.js` 与 `src/host/**` 改完靠插件开关热重载（宿主 HMR 通常会自动重载），`src/ui/**` 改完要 `node build.mjs` 再刷新页面；两边不同步时客户端会退回浏览器 IndexedDB（功能不缺，但书库不跨浏览器共享）。
- **书库列表整本传输**：`books.list` 返回每本书的完整正文（书库界面要用正文算词数与词频），书多了、书大了会偏慢。写进度走的是只传进度的 `books.progress`，不受影响。书库大到几十本以后，下一步是给列表加「只回元数据」的摘要模式。
- **中文按「一字一词」**：没有中文分词器，生词本与词频统计都以**单字**为单位，不是真正的中文词。多音字、成词、虚词都分不出来；要按词统计得引入一个中文分词器。
- **英文的省略号**：U+2026（`…`）现在无条件算句尾，所以 “Wait… what” 这类排版省略号会被切成两句。实测影响很小（那本书里只有 4 处），但英文书大量用 `…` 时要收紧成「后接大写或汉字才断句」。
- **朗读与识别对中文**：本机中文音色只有一个（婷婷），音色要好看得走 MiniMax 云端（64 个中文音色）。
